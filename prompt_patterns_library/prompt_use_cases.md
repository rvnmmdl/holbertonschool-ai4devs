# Prompt Use Cases

This document categorizes common situations where prompt patterns are useful in software engineering workflows.

## 1. Code Quality

### 1.1 Code Refactoring
- **Goal:** Improve code readability, maintainability, and performance.
- **Input:** Existing source code in JavaScript or TypeScript.
- **Output:** Refactored code with an explanation of improvements.

### 1.2 Style Enforcement
- **Goal:** Enforce consistent naming conventions and coding standards.
- **Input:** Source code that does not follow the project's coding standards.
- **Output:** Rewritten code following consistent formatting and naming conventions.

### 1.3 Performance Optimization
- **Goal:** Identify inefficient code and suggest performance improvements.
- **Input:** A function or component with potential performance issues.
- **Output:** Optimized code with an explanation of performance improvements.

## 2. Debugging

### 2.1 Error Diagnosis
- **Goal:** Identify the root cause of a programming error.
- **Input:** Error message, stack trace, and relevant source code.
- **Output:** Explanation of the root cause and suggested solution.

### 2.2 Bug Fixing
- **Goal:** Find and fix bugs without changing existing functionality.
- **Input:** Source code and a description of the unexpected behavior.
- **Output:** Corrected code with an explanation of the fix.

### 2.3 API Troubleshooting
- **Goal:** Diagnose problems with API requests and responses.
- **Input:** API endpoint, request configuration, and error response.
- **Output:** Identified API issue and recommended correction.

## 3. Documentation

### 3.1 Function Documentation
- **Goal:** Generate clear documentation for functions and methods.
- **Input:** Function source code.
- **Output:** Documentation describing parameters, return values, and functionality.

### 3.2 README Generation
- **Goal:** Create project documentation for developers.
- **Input:** Project structure, technologies, and installation requirements.
- **Output:** A structured README.md file.

### 3.3 API Documentation
- **Goal:** Document API endpoints and their usage.
- **Input:** API routes, HTTP methods, parameters, and response structures.
- **Output:** Structured API documentation with request and response examples.

## 4. Testing

### 4.1 Unit Test Generation
- **Goal:** Generate unit tests for individual functions.
- **Input:** Function implementation and expected behavior.
- **Output:** Unit tests covering normal and edge cases.

### 4.2 Integration Testing
- **Goal:** Verify that multiple application components work together correctly.
- **Input:** Component interfaces, dependencies, and expected workflows.
- **Output:** Integration test cases and test code.

### 4.3 Edge Case Identification
- **Goal:** Identify unusual inputs and boundary conditions that may cause failures.
- **Input:** Function requirements and source code.
- **Output:** A list of edge cases with corresponding test scenarios.

## 5. Code Generation

### 5.1 Component Generation
- **Goal:** Generate reusable UI components.
- **Input:** Component requirements, design description, and technology stack.
- **Output:** Reusable React component with appropriate props and styling.

### 5.2 API Integration
- **Goal:** Generate code for connecting an application to an external API.
- **Input:** API documentation, endpoint details, and application requirements.
- **Output:** API integration code with error handling.

### 5.3 CRUD Functionality
- **Goal:** Generate Create, Read, Update, and Delete functionality.
- **Input:** Data model, application requirements, and preferred technology.
- **Output:** CRUD implementation with appropriate functions and validation.
